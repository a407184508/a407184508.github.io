# 模块 A：网页聚合与标签整理

> 优先级：P1（工具箱与工作台稳定后启动）  
> 关联：[产品总览](./00-产品总览.md)

## 1. 目标

把浏览器里散落的**标签页、书签、历史记录、常用网站**自动整理成可检索、可复用的个人资源库，并沉淀为博客的"导航页"与"阅读周报"。

一句话：**打开过的东西不再丢失，收藏过的东西找得回来。**

## 2. 用户故事

- 打开 3 个窗口、50 个标签后，能一键保存为"工作集"，下次一键恢复。
- 收藏的 500+ 书签能自动按主题聚类，不必手动建几十个文件夹。
- 想知道这周最常看什么、新收藏了什么，自动生成一份周报。
- 想找"上周看过的那个讲 XX 的文章"，输入关键词 30 秒内找到。
- 想把自己的常用网站整理成一个公开导航页，放到博客上。

## 3. 功能需求

### 3.1 数据采集（P0）

- 浏览器扩展一键采集当前窗口 / 全部窗口标签页。
- 采集书签；历史记录可选（默认关闭，支持时间范围）。
- URL 归一化去重：去除 utm 等跟踪参数、锚点、尾部斜杠。
- 记录元信息：标题、favicon、域名、访问时间、访问次数、来源。
- 支持手动添加链接、导入浏览器书签 HTML 文件。
- 可选：页面摘要/正文提取（用于后续搜索与 AI 归类）。

### 3.2 自动整理与聚类（P0 / P1）

**P0**

- 按域名自动分组。
- 基于规则的自动打标签（域名白名单、关键词、路径特征）。
- 重复链接合并，保留最早收藏时间与最近访问时间。

**P1**

- 语义相似聚类（同主题不同站点归为一组）。
- 标签体系：层级、别名、合并、颜色。
- 手动修正与批量操作（改标签、移动分组、归档、删除）。
- 失效链接检测（定时任务，标记 404/超时，可一键清理）。

### 3.3 工作集（P0）

- 把当前窗口所有标签保存为一个"工作集"（名称、备注、颜色）。
- 一键恢复工作集；支持跳过已打开页面（增量恢复）。
- 每日自动快照，可回溯"某天我开了哪些页面"。
- 工作集可导出为 Markdown 链接列表。

### 3.4 常用网站与导航页（P1）

- 高频站点排行：按访问次数与停留时间。
- 使用时段分析（例如"工作日上午集中访问文档站"）。
- 个人导航页：分组、图标、备注，可发布到博客。
- 站点级备注与"为什么收藏"记录。

### 3.5 检索（P0）

- 全文搜索：标题、URL、标签、摘要、备注。
- 过滤条件：域名、标签、来源、时间范围、状态（正常/失效）。
- 结果排序：相关度、最近访问、收藏时间。
- 快速打开、批量导出。

### 3.6 周报 / 月报（P2）

- 统计：访问 TOP 站点、新增收藏、主题分布、清理数量。
- 生成 Markdown 或长图，可直接发布到博客。
- 可选 AI 摘要："本周你主要关注了……"。
- 定时生成（每周日）并可选择是否提醒。

### 3.7 扩展盘点（P2，需求待确认）

> "扩展"若指浏览器插件管理，则本项提升为 P1。

- 列出已安装扩展、用途备注、权限概览。
- 标记长期未使用、可停用的扩展。
- 记录扩展与工作流的对应关系。

## 4. 数据模型（初稿）

```
Page
  id, url, urlHash, title, domain, favicon, description, summary
  tags[], source(tab/bookmark/history/manual)
  visitCount, lastVisitedAt, createdAt
  status(active/dead), collectionId

Collection（工作集/分组）
  id, name, type(window/theme/manual), note, color, createdAt

Tag
  id, name, parentId, color, aliases[]

Snapshot
  id, date, pageIds[], windowInfo

Site（站点维度聚合）
  domain, name, note, group, visitCount, lastVisitedAt
```

## 5. 交互与体验要求

- 采集动作 ≤ 1 次点击，结果可撤销。
- 整理过程可见、可回滚，避免"自动整理后更乱"。
- 大数据量（5000+ 条）列表使用虚拟滚动。
- 默认低打扰：不弹窗、不强行引导；周报可选开启。
- 全量导出：JSON / CSV / Markdown，包含标签与分组关系。

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 隐私 | 默认本地存储；调用云端 AI 时仅发送标题/URL/摘要，且可全局关闭 |
| 性能 | 5000 条数据下搜索 < 500ms；列表滚动流畅；导入 1000 条书签 < 10s |
| 兼容 | Chrome / Edge 优先，Safari 视扩展成本后置 |
| 稳定 | URL 归一化规则可配置；采集失败可重试且不丢数据 |

## 7. 本期不做

- 不做公开收藏社区、关注/点赞等社交功能。
- 不做多账号云同步（除非确认多设备为刚需）。
- 不抓取付费墙内容，不做自动登录。
- 不做网页全文永久存档（仅保留摘要与元信息）。

## 8. MVP 范围与验收标准

**MVP 范围**：扩展采集标签 + 书签导入 → 去重 → 域名/规则分组 → 自动标签 → 搜索 → 工作集保存与恢复。

**验收标准**

- [ ] 50 个标签一键保存为工作集，并可完整恢复。
- [ ] 导入 500 条书签后，10 秒内完成去重与分组。
- [ ] 任意关键词搜索 500ms 内返回结果。
- [ ] 所有数据可导出为 JSON，且能重新导入恢复。
- [ ] 关闭扩展后，主站数据仍可正常浏览与搜索。

## 9. 待确认

1. 数据存储位置：浏览器 IndexedDB 本地，还是同步到自建服务端？
2. 是否需要多设备（家里电脑 / 公司电脑）同步？
3. 历史记录是否纳入采集范围？保留多久？
4. "扩展"具体指浏览器插件管理，还是"更多类型的内容"？
5. 是否需要页面正文全文检索？这会显著增加存储与实现成本。
6. 导航页是否公开到博客？公开范围如何控制？
