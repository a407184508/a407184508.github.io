# 模块 B：内容创作工具箱

> 优先级：P0（最先落地）  
> 关联：[产品总览](./00-产品总览.md)

## 1. 目标

把"写一次 → 多平台分发"的重复劳动工具化：

- Markdown 一键排版到微信公众号
- 画布方式制作小红书首图并导出图片
- Markdown 转连续长图 / 内容卡片图

**共同底座**：Markdown 解析 + 主题系统 + 图片导出引擎。

## 2. 子工具与优先级

| 编号 | 子工具 | 说明 | 优先级 |
|---|---|---|---|
| B1 | 公众号 Markdown 排版 | Markdown → 公众号兼容富文本，一键复制 | P0 |
| B2 | Markdown 转长图 | 连续长图 / 自动分页图片 | P0 |
| B3 | 小红书首图画布 | 画布编辑 + 模板 + PNG 导出 | P1 |
| B4 | 内容图 / 配图 | 引用卡、金句卡、数据卡、代码卡 | P2 |
| B5 | 模板与素材库 | 主题、配色、字体、贴纸、背景 | P1 |

## 3. B1 公众号 Markdown 一键排版

### 3.1 功能需求

- **编辑**：左侧 Markdown 输入，右侧实时预览；支持导入 `.md` 文件、从博客文章导入。
- **主题**：内置 5–8 套（简约、杂志、科技、手账等），支持自定义 CSS 变量（主色、字号、行高、间距、圆角）。
- **元素支持**：标题（H1–H4）、段落、加粗/斜体/删除线、有序/无序列表、引用、分割线、图片、表格、代码块（语法高亮）、链接、脚注。
- **一键复制**：生成**内联样式** HTML，粘贴到公众号编辑器后不掉样式。
- **图片处理**：本地上传、自动压缩、宽度适配；圆角/阴影/图注；支持外链图床。
- **草稿与版本**：自动保存草稿，保留最近若干版本可回滚。
- **导出**：复制富文本、导出 HTML、导出 PDF（可选）。

### 3.2 验收标准

- [ ] 复制到公众号编辑器后，样式一致率 ≥ 95%（标题、间距、颜色、图片）。
- [ ] 一篇 10 分钟文章，排版操作 ≤ 3 步。
- [ ] 图片在 2 倍屏下清晰，不出现模糊或拉伸。
- [ ] 主题切换后预览与复制结果一致。
- [ ] 代码块高亮在公众号内可见（使用内联样式或图片降级方案）。

### 3.3 待确认

- 图床方案：自建（如 S3/MinIO）还是第三方？公众号要求图片可外链。
- 是否需要直接调用公众号草稿箱接口发布（需 AppID/Secret，且要处理 IP 白名单）？
- 是否支持多套主题保存与分享（JSON 导入导出）？

## 4. B2 Markdown 转连续长图

### 4.1 功能需求

- 将 Markdown 自动排版为卡片式长图（标题区、正文、引用、代码、表格）。
- **分页策略**：按渲染高度自动切分（默认 1080×1440 或 1080×1920），支持手动调整断点。
- **导出**：单张长图 / 多张分页图 / PDF。
- **主题**：与 B1 共用主题系统；支持深色/浅色。
- **页脚**：署名、页码、进度、水印（可关闭）。
- **细节保护**：标题不落在页尾、代码块不跨页断裂、图片不裁切。

### 4.2 验收标准

- [ ] 3000 字文章 1 分钟内完成导出。
- [ ] 不出现文字截断、代码块断裂、图片裁切。
- [ ] 多张分页图尺寸一致，可直接发布到小红书/朋友圈。
- [ ] 导出图片清晰度满足 2x 屏阅读。

### 4.3 待确认

- 分页尺寸是否需要自定义（如公众号配图 900px 宽）？
- 是否需要"一句话一张图"的金句模式？

## 5. B3 小红书首图画布

### 5.1 功能需求

- **尺寸模板**：3:4（1080×1440）、1:1、4:3、9:16。
- **画布能力**
  - 背景：纯色、渐变、图片、纹理。
  - 文字：字体、字号、行高、字距、颜色、描边、阴影、对齐、竖排（可选）。
  - 图片：上传、裁剪、圆角、蒙版、滤镜（基础）。
  - 形状：矩形、圆形、线条、箭头、标签块。
  - 贴纸/图标：内置少量常用素材。
  - 二维码/署名区（可选）。
- **编辑辅助**：网格、对齐吸附、图层排序、锁定、显示/隐藏、撤销重做、快捷键。
- **模板**：标题式、对比式、清单式、人物封面式；一键换配色/字体。
- **导出**：PNG / JPG，支持 1x/2x；支持多页批量导出。
- **工程保存**：画布工程可保存并再次编辑。

### 5.2 验收标准

- [ ] 从选模板到导出一张合格首图 ≤ 3 分钟。
- [ ] 导出 1080×1440 @2x 图片清晰无锯齿。
- [ ] 文字换行、描边、阴影在导出后与画布一致。
- [ ] 工程保存后重新打开，图层与样式无丢失。
- [ ] 本地缺失字体时有明确降级提示。

### 5.3 待确认

- 首版是否需要 AI 生成背景/配图？
- 是否需要"一次套模板批量生成 6–9 张"？
- 字体版权：仅使用可商用字体，还是允许用户自行导入？

## 6. B4 内容图 / 配图（P2）

统一由画布引擎提供预设模板：

- 引用卡片（书名、文章、播客）
- 金句卡
- 数据卡（大数字 + 说明）
- 代码卡（带语法高亮）
- 文章封面图（博客用）

## 7. B5 模板与素材库（P1）

- 主题/模板以 JSON 形式存储，可导入导出。
- 支持收藏常用模板，设置默认模板。
- 素材（背景、贴纸）本地缓存，避免依赖外链。
- 模板版本兼容：旧工程在新版本中可打开。

## 8. 通用要求

- 全本地处理优先，生成的图片与 HTML **无水印**。
- 草稿自动保存（本地 IndexedDB 或服务端），刷新不丢。
- 导出文件命名：`日期-标题-尺寸.png`，便于归档。
- 所有导出结果可复现：相同输入 + 主题 → 相同输出。
- 支持键盘操作，减少鼠标切换成本。

## 9. 技术建议

| 能力 | 建议方案 |
|---|---|
| Markdown 解析 | unified / remark / rehype |
| 代码高亮 | Shiki（可导出为内联样式） |
| 公众号内联 | juice 或自研 CSS 内联器，配合兼容白名单 |
| 长图导出 | html-to-image；或 Satori + resvg（服务端更稳定） |
| 画布 | Fabric.js 或 Konva |
| 图片压缩 | browser-image-compression / sharp（服务端） |
| 本地存储 | IndexedDB（工程、草稿、主题） |

## 10. MVP 范围

- **第一阶段（P0）**：B1 公众号排版 + B2 Markdown 长图，共用解析与主题系统。
- **第二阶段（P1）**：B3 首图画布 + 基础模板 + 导出。
- **第三阶段（P2）**：B4 预设内容图 + B5 素材库完善。

## 11. 待确认

1. 工具是独立页面还是嵌入博客后台？
2. 是否需要账号体系保存云端草稿，还是纯本地即可？
3. 公众号是否需要对接草稿箱 API 直接发布？
4. 首图是否需要批量生成与模板市场？
5. 图片导出是否需要服务端渲染（更稳定但需要后端）？
